# ADR-0015 — Pré-visualização de mockups no chat (HTML/SVG em iframe isolado)

- **Status:** **Aceito**
- **Data:** 2026-09-10

## Contexto
Ao construir um projeto, o usuário pede à Friday para **gerar um mockup visual**
e quer **vê-lo na hora, dentro do próprio chat** — não só ler o código. Hoje o
chat renderiza markdown com destaque de sintaxe; um bloco ```html aparece apenas
como texto colorido.

## Problema
- Renderizar HTML/SVG gerado pelo modelo **dentro do chat**, sem sair do app.
- O conteúdo é código arbitrário (gerado por um LLM): não pode enxergar o app
  (DOM, `localStorage`, cookies) nem falar com o backend local.
- Enquanto a resposta ainda chega (streaming), o HTML está **incompleto** —
  renderizar a cada token piscaria e desperdiçaria trabalho.

## Decisão
- **Preview inline por bloco renderável.** No renderer de markdown
  (`Markdown.tsx` → `CodeBlock`), blocos com linguagem `html`/`htm`/`svg` ganham
  um toggle **Visualização/Código**; a visualização é o padrão (revela o mockup
  prontamente).
- **Isolamento por `<iframe sandbox="allow-scripts">`** (`CodePreview.tsx`), com
  o conteúdo em `srcDoc`. Sem `allow-same-origin`: o documento roda numa **origem
  opaca** — não acessa o DOM/armazenamento do app nem herda suas credenciais.
  Fragmentos e SVG são embrulhados num documento HTML com base neutra; documentos
  completos (com `<html>`) são usados como vieram.
- **Streaming-aware:** um contexto React informa se a resposta ainda está
  chegando; enquanto sim, mostra-se o **código** (cresce ao vivo) e só ao final a
  prévia é montada — sem flicker.
- **Layout:** controles de **largura** (desktop/mobile, p/ conferir a
  responsividade do mockup) e **tela cheia**; o quadro é redimensionável
  (CSS `resize`) e a barra adapta-se a telas estreitas.
- **Prompt de código:** o `code_system_prompt` passa a pedir, para mockups, um
  **único HTML autocontido** (sem CDN/fontes/imagens remotas) — assim a prévia
  funciona offline e isolada.

## Justificativa
- `sandbox` sem `allow-same-origin` é a forma padrão e suficiente de embutir a
  saída do próprio assistente do usuário: isola o app sem exigir um servidor de
  preview à parte (mantém o princípio 100% local).
- Mostrar o código durante o streaming e revelar a prévia no fim dá o melhor dos
  dois mundos sem custo de re-render.

## Impactos
- **Frontend:** `components/CodePreview.tsx` (novo); `Markdown.tsx` (detecção +
  toggle + contexto de streaming); `MessageList.tsx` (passa `pending`);
  `styles.css` (barra, quadro, tela cheia, larguras).
- **Backend:** `settings.code_system_prompt` (orientação de mockup autocontido).
- **Fora de escopo (futuro):** auto-altura do iframe via `postMessage`; preview
  de outras linguagens (ex.: Markdown/mermaid dentro do bloco); "abrir no editor"
  a partir da prévia.
