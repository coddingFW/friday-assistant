# ADR-0013 — Workspace de código: projeto local (leitura) + roteamento p/ modelo de código

- **Status:** **Aceito**
- **Data:** 2026-09-08

## Contexto
O usuário quer que a Friday ajude a **construir e ensinar programação** sobre um
**projeto salvo localmente**: apontar uma pasta e trabalhar nela. Até a Fase 9 a
Friday não tocava no sistema de arquivos, e o modelo de conversa (`llama3.1:8b`)
é fraco em código.

## Problema
- Dar acesso a arquivos de um projeto local, offline, **sem vazar** para fora da
  pasta escolhida (segurança de caminho).
- Não bloquear o event loop com I/O de disco.
- Usar um modelo bom em código **sem** trocar o modelo de conversa geral.
- Manter a Friday boa em **ensinar** (explicar, código completo), não só entregar.
- Escopo controlado: nesta fatia ela **lê e ensina** — não escreve (decisão do
  usuário; escrita com confirmação fica para um incremento futuro, com salvaguardas).

## Decisão
- **Camada nova `backend/workspace/`** (Ports & Adapters, como `memory/`):
  `ports.py` (modelos `TreeEntry`/`FileContent`/`SearchHit` + porta
  `WorkspaceProvider`), `providers/local_fs.py` (`LocalFsWorkspace`), `factory.py`,
  `service.py` (`WorkspaceService` — fachada + montagem do bloco de contexto).
- **Somente leitura**, **confinado à raiz**: caminhos resolvidos com
  `Path.resolve()` e recusados se saírem da raiz (bloqueia `..`/symlink); binários
  e arquivos grandes são recusados/truncados; diretórios de ruído
  (`node_modules`, `.git`, `.venv`…) são ignorados. I/O em `asyncio.to_thread`.
- **Roteamento por contexto** (mesmo padrão da visão): quando a mensagem traz
  `context_files` (arquivos do projeto), o turno é de **código** — usa
  `FRIDAY_CODE_MODEL` (default `qwen2.5-coder:7b`), o **prompt de ensino**
  (`code_system_prompt`) e **pula o RAG web**. Conversa geral continua no
  `llama3.1`. Nenhum outro modo é afetado.
- **REST** (`/api/workspace`): `POST/GET root`, `GET tree`, `GET file`,
  `GET search`. Enviar a mensagem que usa os arquivos continua no WebSocket
  (`UserMessage.context_files`).

## Justificativa
- Reusa o estilo consolidado (porta + fábrica + serviço) e o roteamento de modelo
  já usado na visão (ADR-0011) — mínimo de conceito novo.
- Confinar à raiz + só leitura mantém o risco baixo com um modelo local (que erra
  mais que um de ponta): a Friday não altera nada por conta própria.
- Modelo de código à parte preserva a qualidade da conversa em PT-BR.

## Impactos
- **Backend:** pacote `workspace/`; `settings` (`code_model`,
  `code_system_prompt`, `workspace_enabled`, limites e ignore); `utils/errors`
  (`WorkspaceError`); `api/dependencies` (`get_workspace_service`);
  `api/rest/workspace.py`; `UserMessage.context_files`; `chat.py` (lê os arquivos
  → `context_blocks`); `conversation.py`/`rag/service.py` (turno de código:
  `build_code_messages`, seleção do `code_model`, RAG pulado); registro no lifespan.
- **Pré-requisito do usuário:** `ollama pull qwen2.5-coder:7b`.
- **Frontend:** apontar a pasta, árvore de arquivos e seleção de contexto são o
  **próximo incremento** (esta fatia entrega o backend + REST + WS).
- **Fora de escopo (futuro):** escrita/edição de arquivos (com confirmação,
  restrita à raiz, backup/git), execução de comandos, indexação semântica.
