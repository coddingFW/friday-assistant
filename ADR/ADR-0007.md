# ADR-0007 — Síntese de voz no Host, reprodução no cliente

- **Status:** **Aceito**
- **Data:** 2026-08-01

## Contexto
A Fase 4 adiciona voz (TTS Piper, ADR-0003). Surge a decisão central: **onde o
áudio é reproduzido** — no Host (backend) ou no cliente (navegador/Tauri/mobile)?

## Problema
Reproduzir no Host faria o som sair **na máquina do Host**, não no dispositivo do
usuário. Isso quebra a topologia Host+Cliente (ADR-0001): um cliente mobile na LAN
nunca ouviria a resposta. Também acoplaria o backend a um dispositivo de áudio.

## Alternativas
1. **Tocar no Host** (biblioteca de áudio no backend) — simples localmente, mas
   inviável para clientes remotos; acopla o backend a hardware de áudio.
2. **Sintetizar no Host, enviar ao cliente** — o backend gera o WAV (Piper) e o
   transmite; o cliente reproduz. Consistente com "Brain nunca toca dispositivo".

## Decisão
Adotar a alternativa 2. O **Host sintetiza** (Piper, via porta `TTSProvider`,
Strategy) e **o cliente reproduz**. O áudio trafega no evento WebSocket
`audio` (WAV em base64), emitido após a resposta em texto. O frontend reproduz
automaticamente e oferece um botão "Ouvir" para repetir.

Versão inicial: sintetiza a **resposta completa** ao final da geração (Piper é
rápido). Streaming por sentença + visemas fica para a Fase 5 (avatar).

## Justificativa
- Cumpre a topologia Host+Cliente e prepara o mobile (o som sai no dispositivo do
  usuário, não no Host).
- Mantém o backend agnóstico de hardware de áudio (só produz bytes).
- Degradação graciosa: se o TTS falhar/estiver desligado, o texto já foi entregue;
  o áudio é simplesmente omitido.

## Impactos
- Backend: camada `backend/tts/` (porta + adapter Piper + fábrica), evento de
  domínio `AudioReady`, e síntese em `ConversationService` (atrás de `tts_enabled`).
- Protocolo WS: novo evento `audio` (mime + base64).
- Frontend: reproduz o áudio recebido (autoplay + botão "Ouvir").
- Dependência: `piper-tts` (Python; traz `onnxruntime`). Modelo de voz `.onnx`
  PT-BR baixado à parte (não versionado).
- Latência: síntese após a resposta completa; aceitável (Piper >> LLM em CPU).
