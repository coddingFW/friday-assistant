# ADR-0002 — LLM via Ollama com modelo configurável; STT com faster-whisper

- **Status:** Aceito (aprovado pelo arquiteto)
- **Data:** 2026-08-01

## Contexto
O sistema precisa de um LLM local e de reconhecimento de voz local, ambos
offline e sem APIs pagas. O arquiteto pediu que o modelo do LLM seja
**configurável**, não fixo, com suporte futuro a `llama3.1`, `qwen3`, `mistral`,
`gemma`, `deepseek`, `phi`.

## Problema
1. Acoplar o backend a um modelo/provedor específico impediria a troca fácil.
2. Escolher entre Whisper e Vosk para STT.

## Alternativas
- **LLM provider:** Ollama (serve múltiplos modelos) vs. integração direta com um runtime.
- **STT:** faster-whisper (Whisper, mais preciso em PT-BR, mais pesado) vs. Vosk (leve, streaming nativo, menos preciso).

## Decisão
1. **LLM:** provedor **Ollama**, modelo default `llama3.1:8b`, **trocável apenas
   por configuração** (`FRIDAY_LLM_MODEL`). A seleção de provedor é um **Strategy
   Pattern** (`backend/brain/factory.py` + porta `LLMProvider`), permitindo
   adicionar outros provedores no futuro sem tocar no domínio.
2. **STT:** **faster-whisper** (implementação Whisper via CTranslate2).

## Justificativa
- O Host é um PC com folga de hardware; prioriza-se qualidade de PT-BR (Whisper).
- Ollama já abstrai múltiplos modelos; a troca vira configuração pura.
- A porta + fábrica garantem baixo acoplamento (SOLID/DIP).

## Impactos
- `backend/brain/ports.py` define o contrato; `OllamaProvider` é o primeiro adapter.
- Vosk permanece possível como estratégia alternativa de STT (Fase 6), sem custo arquitetural.
- Ollama e modelos são serviços/artefatos externos instalados no Host.
