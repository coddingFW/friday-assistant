# ADR-0016 — OCR dedicado (Tesseract) como OnDemandSensor

- **Status:** **Aceito**
- **Data:** 2026-09-10

## Contexto
A Fase 8 (visão) já entrega imagem/tela ao LLM de visão (`llava`), que
*interpreta* a figura. Falta a transcrição **literal** do texto contido numa
imagem — ler exatamente as palavras de um print, documento, nota ou mensagem de
erro. O `PROJECT_MANIFEST` já previa a modalidade `OCR_TEXT` e a porta
`OnDemandSensor`; o ADR-0011 deixou o OCR dedicado como evolução.

## Problema
- O LLM de visão *descreve* ("parece um documento"), mas pode alucinar caracteres;
  para copiar/raciocinar sobre o texto exato é preciso OCR de verdade.
- Restrição do manifesto: 100% local, sem chave/API paga.
- O OCR precisa de uma **imagem de entrada** (upload do cliente ou captura de
  tela) — diferente do `ScreenCaptureSensor`, que lê do dispositivo.

## Decisão
- **`OcrSensor` (OnDemandSensor)** em `perception/sensors/ocr.py`, emitindo
  `Percept(OCR_TEXT, text/plain)`. Usa **Tesseract** via `pytesseract` + `Pillow`.
  O motor (`OcrEngine = (bytes, lang) -> str`) é **injetável** — testes rodam sem
  o binário. `capture(image=bytes, lang=...)` roda o reconhecimento num worker
  thread (bloqueante).
- **Config:** `FRIDAY_OCR_ENABLED` (default True, sob `vision_enabled`),
  `FRIDAY_OCR_LANG` (default `por+eng`), `FRIDAY_OCR_TESSERACT_CMD` (caminho do
  binário quando fora do PATH — comum no Windows) e `FRIDAY_OCR_TESSDATA_DIR`
  (diretório de idiomas gravável quando o `tessdata` da instalação não é — ex.:
  Program Files; aplicado via `TESSDATA_PREFIX`, seguro para caminhos com espaço).
- **Endpoint:** `POST /api/vision/ocr` com `{ source: "upload"|"screen", image?,
  lang? }`. `screen` captura a tela (reusando o `ScreenCaptureSensor`) e faz OCR;
  `upload` recebe a imagem em base64. Devolve `{ text, lang, chars }`.
- **Degradação clara:** sem o Tesseract instalado/encontrado, o motor levanta
  `OcrUnavailableError` (subclasse de `SensorError`) → HTTP 503 com orientação de
  instalação. Pré-requisito do usuário, análogo a `ollama pull llava`.
- **Frontend:** botão 🔤 no `Composer` — faz OCR da imagem anexada (ou, sem
  imagem, da tela) e **insere o texto no campo de mensagem** para o usuário
  editar/perguntar.

## Justificativa
- Reusa a camada de sensores (porta OnDemand, registry, `snapshot`) e o
  `ScreenCaptureSensor` já existentes — mínimo de código novo, zero mudança no
  Brain. Motor injetável mantém os testes independentes do binário.
- Tesseract é o motor de OCR local de referência, open-source, offline.

## Impactos
- **Backend:** `settings` (`ocr_enabled`, `ocr_lang`, `ocr_tesseract_cmd`);
  `errors` (`OcrUnavailableError`); `perception/sensors/ocr.py`;
  `api/rest/vision.py` (`POST /vision/ocr`); registro no lifespan (`main.py`).
  Dep nova: `pytesseract` (+ o binário do Tesseract, instalado pelo usuário).
- **Frontend:** `api.runOcr`; `useChat.ocr`/`ocrBusy`; botão 🔤 no `Composer`.
- **Pré-requisito do usuário:** instalar o Tesseract (Windows:
  https://github.com/UB-Mannheim/tesseract/wiki) com o traineddata de `por`/`eng`;
  se fora do PATH, apontar `FRIDAY_OCR_TESSERACT_CMD`. Nesta máquina: instalado em
  `C:\Program Files\Tesseract-OCR` (v5.4.0, fora do PATH), e como a pasta
  `tessdata` da instalação não é gravável, os idiomas `por`/`eng`/`osd` ficam em
  `models/tessdata/` (gitignored) via `FRIDAY_OCR_TESSDATA_DIR`. Validado ao vivo
  com texto PT acentuado.
- **Limitações / evolução:** sem pré-processamento de imagem (deskew/threshold);
  idioma fixo por config (troca por captura via `lang`). Webcam
  (StreamingSensor) segue como incremento futuro.
