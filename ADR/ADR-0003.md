# ADR-0003 — Síntese de voz (TTS) com Piper

- **Status:** Aceito (aprovado pelo arquiteto)
- **Data:** 2026-08-01

## Contexto
A assistente precisa falar com voz natural, offline, sem serviços pagos, e a voz
deve alimentar a sincronização do avatar (Fase 5).

## Problema
Escolher entre pyttsx3 (vozes do SO, zero setup, robótica) e Piper (neural,
natural, exige baixar modelo `.onnx`).

## Alternativas
- **pyttsx3:** trivial, mas robótico e inconsistente entre SOs (SAPI5 no Windows).
- **Piper:** voz neural natural, vozes PT-BR, mesma voz em Windows/macOS, base para visemas.

## Decisão
Adotar **Piper** como estratégia de TTS.

## Justificativa
Qualidade neural, consistência entre plataformas (essencial para a portabilidade
definida no ADR-0001) e melhor base para sincronizar fala↔avatar.

## Impactos
- Será necessário baixar um modelo de voz PT-BR (`.onnx`) no Host (Fase 4).
- A camada `tts/` seguirá o mesmo padrão porta+adapter do LLM (Strategy),
  mantendo pyttsx3 como fallback possível sem custo arquitetural.
