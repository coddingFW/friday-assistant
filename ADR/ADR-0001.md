# ADR-0001 — Frontend em Tauri 2.0 + React (em vez de PySide6)

- **Status:** Aceito (aprovado pelo arquiteto)
- **Data:** 2026-08-01

## Contexto
O contrato previa `frontend/main.py` (Python, isto é, PySide6). O arquiteto
definiu como objetivo a longevidade da arquitetura, com evolução para desktop
(Windows/macOS/Linux), cliente mobile (Android/iOS) na LAN e possivelmente web,
**sem reescrever o backend**.

## Problema
PySide6 não oferece caminho realista para mobile. Manter o frontend em Python
acoplaria a apresentação ao runtime do backend, contrariando o requisito de
clientes múltiplos e desacoplados.

## Alternativas
1. **PySide6 (Qt):** simples no curto prazo, tudo em Python; sem mobile viável.
2. **Tauri 2.0 + React (TS):** desktop + mobile de uma base; comunica só via HTTP/WS.

## Decisão
Adotar **Tauri 2.0 + React + TypeScript**. A subárvore `frontend/` deixa de ser
Python; o backend permanece 100% independente da interface.

## Justificativa
O contrato já exige que o frontend só fale REST/WebSocket, o que anula a única
desvantagem do Tauri (não compartilhar processo com Python). Ganha-se
portabilidade real e UX web moderna (avatar em canvas/WebGL).

## Impactos
- Ambiente de dev do frontend exigirá Node.js + Rust + WebView2 (Fase 3).
- Backend inalterado a cada novo cliente — objetivo central atendido.
- Custo aceito: maior complexidade inicial de setup do frontend.
